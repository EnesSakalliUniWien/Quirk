## Prioritized findings

### FND-01 — P2: State table omits most rows from assistive technology

Evidence: src/components/panels/state/state-panel.jsx:158 renders rows.slice(start,end), with aria-hidden spacer rows at lines 49,157,189. src/components/panels/state/useVisibleRows.js:60–91 changes its range only on scroll/resize; the enclosing scroll div at state-panel.jsx:117 has no row navigation or paging controls. aria-rowcount at :122 and aria-rowindex at :159 describe positions but cannot provide the contents of rows absent from the DOM. A large superposition thus presents only a visible subset through table navigation. The root agent confirmed this DOM omission live: 256 states expose 24 mounted rows, and scrolling changes the range without nearby explicit paging controls. Whether Safari VoiceOver can conveniently induce sufficient scrolling remains unverified. Export is an alternate data route, not an equivalent in-place table inspection.

HIG: [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [VoiceOver](https://developer.apple.com/design/human-interface-guidelines/voiceover) ask that information and interactive infographics remain accessible. Minimum recommendation: give this existing table explicit Previous/Next rows controls and an announced range, or a labelled basis-row input that scrolls/renders the requested row. Reuse visibleRowRange and existing native inputs; avoid a second hidden 4096-row table or a new virtual-grid framework. Verify a large superposition with VoiceOver table navigation and keyboard before claiming full alignment.

### FND-02 — P3: Text sizing overrides the browser's preferred default

Evidence: src/styles/foundation/document.css:5 sets html font-size to --font-size-root; src/browser/theme/dom.js:33 generates a fixed 16px root from src/appearance/typography.js:5. Most shared sizes are rem-based, but Forge explanatory/error copy stays 12px at src/styles/panels/forge/construction.css:7,26–27 and matrix headings 11px at :41. Browser page zoom still scales these, so this does **not** establish that 200% zoom fails. The root agent confirmed this live with Page.setFontSizes standard32/fixed26: root and body remained 16px, and Forge description remained 12px (input-evidence.json). Changing the rem root alone would leave some important copy behind.

HIG: [Typography](https://developer.apple.com/design/human-interface-guidelines/typography), [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), [Layout](https://developer.apple.com/design/human-interface-guidelines/layout). Minimum recommendation: use the browser's default root (100%) and existing text tokens for Forge copy; keep precise scientific canvas sizing under circuit zoom. Verify 200% browser zoom and larger default font at narrow widths first. Native Dynamic Type APIs are not a web implementation requirement; CSS pixels are not a direct violation of Apple's native point-size tables.

### FND-03 — P3: Custom palettes have no increased-contrast adaptation

Evidence: src/appearance/Appearance.js:8 selects only dark/light; src/browser/systemColourScheme.js:5 watches only prefers-color-scheme. A current search found no prefers-contrast or forced-colors handling in src or test. Light/dark palettes contain substantial contrast improvements already, so this is a preference-support gap, not evidence that all ordinary text fails contrast. HIG [Color](https://developer.apple.com/design/human-interface-guidelines/color) explicitly asks custom color variants to work in increased-contrast contexts; [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) permits acceptable default contrast but recommends adaptation.

Minimum recommendation: first measure actual troublesome boundaries/text under increased contrast; strengthen the existing neutral control/focus tokens using prefers-contrast: more and appropriate forced-colors rules where the browser reports them. Preserve the scientific phase wheel and numeric phase alternatives; do not flatten scientific colors into arbitrary status colors. Avoid a third complete palette until measured gaps require one. OS-to-browser preference propagation itself needs Safari verification.

### FND-04 — P3: Export section uses an implementation term as its main label

Evidence: src/components/panels/export/export-panel-body.jsx:64 labels the primary share action “Escaped link”; :65 explains special characters that confuse forums. HIG [Writing](https://developer.apple.com/design/human-interface-guidelines/writing) and [Inclusion](https://developer.apple.com/design/human-interface-guidelines/inclusion) favor familiar, action-oriented terms and definitions of technical language. This is an editorial improvement, not a broken workflow. Minimum recommendation: rename the section “Circuit link” and retain any short compatibility explanation only if useful. Existing “Copy to clipboard” control already says the action. Keep “amplitude”, “phase”, “density matrix”, and independent Steps/Time semantics: these are meaningful domain terms and several already have explanatory text.
